# Active game screen

- **Win dialogs freeze the screen:** on a leg or match win, `ActiveGameScreenModel.endTurn` keeps rendering the engine from *before* `endTurn` and holds the (already saved) result in `pendingWinEngine`. Continue swaps it in under the still-open dialog (`continueToNextLeg`), and the UI closes it a frame later (`closeLegWonDialog`); Finish only pops the screen with the dialog up. Either order the other way flashes the ended game without its dialog. The dialog's Undo just closes the dialog and is ignored once Continue swapped, and the Roulette/Practice results dialogs read `state.resultState`.
- **Win dialogs are drawn in the screen, not in a dialog window** (`components/WinDialog.kt`): a window is torn down before the screen slides away, so Finish showed the bare game for a few frames, and it was centred over the darts row. The card sits below the header (`HeaderThenInput` reports its height; with less than 200 dp left there it may use the whole screen and rises over the header only as far as its height needs) and leaves with the screen. Since there's no window, the screen does what it did: the scrim swallows touches and also covers the top bar, `BackHandler` ignores Back, TalkBack only sees the card, and Undo/Continue/Finish are ignored once the screen is no longer on top (`popFrom`, `canNavigateFrom`) so a tap during the slide can't pop twice. Abandon and Knockout stay `AlertDialog`s.
- **The input never moves mid-turn:** nothing above the keypad or dartboard may change height during a game. The checkout hint lives in a fixed-height slot (`components/CheckoutHint.kt`, reserved for modes where `ActiveGameState.hasCheckoutSlot` is true) that is blank when there's no route. In Parcheesi the same slot shows a knockout suggestion ("KO Bob: T7", from `domain/game/KnockoutCalculator.kt`) when no checkout route is shown; the choice is `ActiveGameState.checkoutSlotHint(showCheckoutHints, showKnockoutHints)`, checkout first. Reserve space for anything else that comes and goes (e.g. the Practice "Remaining" line) instead of adding or removing rows. Score-card lines stay on one line (the font shrinks instead of wrapping). Player names on the score cards and the Cricket scoreboard use `components/PlayerNameText.kt`: they shrink to fit down to 10 sp (`MinPlayerNameFontSize`), and only a name still too wide at that size is cut with an ellipsis (4 players on a 360 dp phone). The input gets the height that's left (`HeaderThenInput` in `ActiveGameScreen.kt`, math in `components/InputFit.kt`): the radial board is min(width, height left), with a 220 dp floor, and grid rows shrink to 28–40 dp, so short phones don't scroll. Tall phones keep the full-width board.
- **Scoreboard mode** (`components/ScoreboardView.kt`, setting `scoreboardMode`, toggled from the top bar or Settings): a separate, always-dark view drawn *instead of* the Scaffold while `ActiveGameState.showsScoreboard(...)` is true, so it never touches the input layout. `isScoringOpen` is set by tapping the view (`openScoring`) and cleared when the turn passes on (non-win `endTurn`) and in `closeLegWonDialog`, never in `continueToNextLeg` (the dialog is drawn in the game screen, so it must stay up until it closes). Undo keeps the game screen. Its text sizes are design dp converted to sp (`ScoreboardSizes.sp`), not sp, so the system font size can't push the standings off the screen; the standings rows also shrink to the height left. It calls `KeepScreenOn(true)` only while the Keep Screen On setting is off: its `onDispose` clears the flag, which would otherwise switch off the setting's own keep-on in `App.kt`. The big text uses the bundled `font/roboto_condensed_bold.ttf` (Latin and Latin Extended-A only; licence in `files/licenses/`), so route text replaces the checkout slot's "→" with spaces.
- **Cricket pad:** Cricket uses `CricketInputPad` (layout in `CricketPadLayout.kt`) instead of the grid or the radial board, whatever the keypad settings (like Roulette's `RouletteInputPad`): only the game's `CricketSegments` in the scoreboard's order (Bull only where it lists 25; a Random game without the bull has no Bull key), then Miss, in two rows. Darts on other numbers, and in the bull when it isn't a target, are entered as Miss. Its keys are the grid's `ScoreButton`/`BullButton`, so S/D/T, swipe, preview and TalkBack behave the same. On short phones `HeaderThenInput` shrinks the Cricket scoreboard rows (compact layout, 24–36 dp, from the viewport only, so it never changes mid-game) until the pad fits; tall phones keep the full scoreboard.
- **Swipe input on keys:** with S/D/T buttons off, the grid keys (`ScoreInputKeypad`) are disabled Buttons, and a disabled Button's clickable still consumes the down and the up in the Main pass. Their single tap/swipe handler (`keySwipeInput`) therefore runs in `PointerEventPass.Initial`; a detector in the default pass never sees a plain tap. Tap and swipe are classified on lift by `classifyKeySwipe` (`components/SwipeMultiplier.kt`, on top of the `verticalSwipeMultiplier` the radial board's vertical mode uses), which the live D/T preview shares. For the same reason `keyAccessibility` replaces the disabled Button's semantics (click = single, custom actions Double/Triple), or TalkBack reads the keys as disabled.
- **Swipe pill** (`components/MultiplierIndicator.kt`): DOUBLE and TRIPLE are the same opaque pill with a 3 dp `colorScheme.surface` outline and a shadow, so the brand-red DOUBLE keeps its edge over the red wedges (issue #33). The radial board shows it full size in its centre; the grid and Cricket pads show the `compact` size above their first key row (`Modifier.aboveKeys`, taking no height), because over the keys it hid 17–19 and below them the swiping hand covers it. There it covers the checkout slot (grid) or Undo (Cricket) while a swipe shows it. It's a plain `Box`, not a `Surface`, which would block touches to the bull and Undo, and it hides with no exit animation.
- **Parcheesi dart that didn't count** (exact target without the double-out double, `ActiveGameState.parcheesiNonCountingDarts`; in Game Details `parcheesiNonCountingDarts(leg, config)`): it keeps its normal multiplier chip and gets `Modifier.nonCountingDartChip` (`components/NonCountingDart.kt`): a 2 dp error-coloured ring with a 1 dp surface-coloured gap line inside it, and a 12 dp error-coloured ✕ badge in the top-right corner, cased in the surface colour; the label sits 3 dp lower (`nonCountingDartLabel`) so the badge clears even "T20". TalkBack hears one node, "T1, didn't count". Only singles and trebles can be void, and red on the dark theme's amber treble is ~1.1:1, hence the casing. Rejected (#29): a grey chip (read as an empty slot), a strike through the label (too faint, or it hid the glyphs), a ring alone (read as selected), a badge alone (read as a remove button). While it's the last dart the turn total slot says NO DOUBLE (BUST/BOUNCE size, in grey: not BUST's red, as no score is lost; shrunk to one line).
- **"Last:" during a bounce turn:** the score card's "Last:" line shows finished turns from the session, except that a Parcheesi bounce, which ends the turn on the dart, makes the throwing player's card read BOUNCE at once (`ActiveGameState.getLastTurn`, keyed on `isBounced` like the turn total slot), not only after End Turn (#38). A Classic bust still shows the previous turn until End Turn.
- **Brand red as text:** `colorScheme.primary` (#C62828) is the fill colour (buttons, badges, white on red) and is too dark as text on the dark theme's greys. Score highlights and labels in brand red (Cricket PTS, points and closed marks, the turn summary, the current player's score, results and leaderboard values, "Throwing Order:", settings section headers) use `MaterialTheme.brandColors.text` (`ui/theme/BrandColors.kt`, lighter red in dark theme; `textOnContainer` on default cards and the Cricket PTS tint). `BrandColorsTest` checks 4.5:1 on each surface. The current player's card border and the Cricket PTS strip's tint use `brandColors.highlight` (same red as the text: lighter in dark theme, brand red in light), so frame and text read as one red. Exceptions that stay `colorScheme.primary`: the avatar selection ring (a border, not text), and Material controls' default colours (buttons, radio buttons, text fields). Dialogs' text buttons are the exception to that: they take `dialogTextButtonColors()`, as the default label is ~2.5:1 on the dark dialog surface.
- **Current player's card fill** is `currentPlayerCardColor(colorScheme)` (`ui/theme/BrandColors.kt`): the 30% `primaryContainer` tint pre-blended over the background. Keep elevated cards' fills opaque: a translucent fill lets the elevation shadow show through as a grey frame inside the border (light theme, issue #32).
- **Multiplier colors:** anything color-coded by multiplier uses `MaterialTheme.multiplierColors` (`ui/theme/MultiplierColors.kt`): triple is amber, double is brand red. S/D/T selectors reuse `components/MultiplierButton`. Don't use Material `tertiary` or `primary` for multipliers; `tertiary` is still fine for other things.
